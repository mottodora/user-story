# ユーザーストーリー一覧

このディレクトリには、User Story Mapping Toolの機能をユーザーストーリー形式で記録したドキュメントが含まれています。

## 目的

- プロダクトの機能を体系的に管理
- 各機能の目的、背景、実装の詳細を記録
- 新しいチームメンバーのオンボーディングをサポート
- 機能の変更履歴を追跡

## ドキュメント形式

各ユーザーストーリーは以下の構造で記録されています：

- **ユーザーストーリー**: As a / I want / So that 形式
- **背景**: 機能が必要とされた理由
- **受け入れ基準**: 機能が満たすべき条件
- **実装の詳細**: コンポーネント、API、設計の詳細
- **テストシナリオ**: 正常系・異常系のテストケース
- **関連リソース**: PR、スクリーンショット、関連ドキュメント
- **変更履歴**: 機能の変更履歴

## 命名規則

ユーザーストーリードキュメントは以下の命名規則に従います：

```
US-XXX-<feature-name>.md
```

- `XXX`: 3桁の連番（001, 002, ...）
- `<feature-name>`: 機能名をケバブケース（小文字、ハイフン区切り）で記述

例: `US-001-activity-deletion.md`

## 新しいユーザーストーリーの作成

新しい機能を実装する際は、以下の手順でユーザーストーリーを作成してください：

1. 次の連番を確認（例: US-002）
2. `US-XXX-feature-name.md` という名前でファイルを作成
3. テンプレートに従ってドキュメントを記述
4. このREADMEの一覧表を更新
